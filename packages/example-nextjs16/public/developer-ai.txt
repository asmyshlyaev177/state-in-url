# Technical Context for state-in-url

Website: [https://state-in-url.dev](https://state-in-url.dev)
Last Updated: 2026-07-31

## Overview

state-in-url is an npm package, not a hosted service. It is a set of React hooks that keep a typed, JSON-serialisable state object synchronised with the browser's query string, so nested state survives a reload and can be shared as a link. About 2 KB, no runtime dependencies, MIT licensed.

This website is the package's documentation and live demo. Editing the form on the homepage rewrites the URL in real time, which is the fastest way to see what the library does.

## API Information

status: not-available

There is no hosted HTTP API and no account system. The package runs entirely in the user's application, in the browser and during server rendering. The website is a Next.js App Router application deployed as static and server-rendered pages.

The library's public interface is the set of TypeScript exports listed below.

## API Surface

```typescript
const { urlState, setState, setUrl, reset } = useUrlState(DEFAULT_STATE, options?);
```

- `urlState` — the current state, typed identically to `DEFAULT_STATE`.
- `setState(value)` — updates internal state synchronously. Does not touch the URL.
- `setUrl(value, opts?)` — updates state and URL. The URL write is throttled to the next tick.
- `reset(opts?)` — returns state and URL to `DEFAULT_STATE`.

Setters accept a partial patch, a function of the current state, or a function of `(current, initial)`. Calling `setUrl()` with no argument flushes the current state to the URL.

Per-call options: `replace` (default `true`), `scroll` (default `false`), and any React Router `NavigateOptions`. Hook-level options: `searchParams`, required for correct server rendering in the Next.js App Router, and `useHistory` (Next.js only, default `true`), which uses `window.history.pushState` to avoid `_rsc` round-trips on URL changes.

## Constraints

These are enforced by the type system or by the sharing model, and are the source of most integration bugs:

- The default-state object must be declared with `type`, not `interface` — the `JSONCompatible<T>` constraint rejects interfaces.
- The default-state object must be a module-scoped `const`. Sharing is keyed by object identity, so building it inside a component silently breaks sharing.
- Only JSON-serialisable values plus `Date` round-trip. Functions, `BigInt`, `Symbol`, `Map`, `Set`, and class instances do not.
- Keep the total query string under roughly 12 KB; Vercel's header limit is 14 KB.
- `moduleResolution` must be `Bundler`, `Node16`, or `NodeNext`.
- Next.js Pages Router is not supported.

## Security

No secrets in the URL. Entity identifiers such as `jobId` or `memberId` are the intended use; tokens, API keys, and personal data are not, because URLs reach browser history, server logs, referrer headers, and screenshots.

Report security issues through [GitHub issues](https://github.com/asmyshlyaev177/state-in-url/issues).
